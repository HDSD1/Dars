# 当前 DRL 框架详细说明 (V19, 2026-04-16)

## 一、MDP 建模

### 状态空间 (dim=105)
```
s(t) = [
    电池电量 (K=4),                     # 各 UAV 当前电量 [0, E_INIT]
    UAV 2D 位置 (2K=8),                 # 各 UAV 的 (x, y)
    用户 2D 位置 (2M=40),               # 各 GU 的 (x, y)
    任务大小 (M=20),                    # 各用户任务 (0=无任务)
    active_mask (M=20),                # 哪些用户有任务 (0/1)
    WCT 距离信息 (3K=12),              # ★ 每 UAV: (到最近WCT距离/L, 方向x, 方向y)
    归一化时间步 (1),                   # current_step / SLOT_NUM
]
```

### 动作空间 (dim=32, 连续, ∈ [-1, 1])
```
a(t) = [
    UAV 飞行 cos(θ) (K=4),              # ★ cos 分量 [-1, 1]
    UAV 飞行 sin(θ) (K=4),              # ★ sin 分量 [-1, 1]
    UAV 飞行速度 (K=4),                 # v_k, 映射到 [0, V_max=50m/s]
    用户卸载比例 (M=20),                # x_i, 映射到 [0, 1]
]
注: 每架 UAV 3 维动作 (cos, sin, speed), 角度 θ = atan2(sin, cos)
    消除了旧方案中 θ=0 和 θ=2π 的不连续性
```

### 奖励函数
```python
r(t) = M × [ω_t × mean(ρ_active) + ω_e × η_E] - battery_penalty

其中:
  mean(ρ_active) = 只对有任务的用户计算延迟缩减比的均值, ∈ [0,1]
  η_E = E_charge / E_consume, ∈ [0,1]  (所有 UAV 汇总)
  M = 20, ω_t = 1.0, ω_e = 0.6

  battery_penalty = 5.0 × Σ(max(0, 0.3 - battery_ratio))²
  无死亡惩罚 — 电量耗尽直接终止, 失去后续奖励即隐式惩罚
```

### Episode 结构
```
- 最大步数: T_slot = 40 步
- 每步时间: τ = 8s = 飞行1s + 悬停/服务7s
- 终止条件: 任一 UAV 电量 ≤ 0, 或达到 40 步
```

## 二、网络架构 (PER-TD3-DDPG)

### Actor 网络
```
Input(105) → FC(400) → LayerNorm → ReLU
           → FC(300) → LayerNorm → ReLU
           → FC(32)  → Tanh × 1.0
```

### Twin Critic 网络 (×2 独立 Q 网络)
```
Input(105+32=137) → FC(400) → LayerNorm → ReLU
                  → FC(300) → LayerNorm → ReLU
                  → FC(1)   → Q值
```

## 五、V19 vs V17 改进对比

| 维度 | V17 | V19 | 预期效果 |
|------|-----|-----|---------|
| γ | 0.9 (10步视野) | **0.99 (100步)** | 充电的长期收益不被折扣抹零 |
| 角度表示 | 标量 θ | **cos/sin** | 训练更平滑, 无方向跳变 |
| 状态信息 | 原始坐标 | **+WCT距离方向** | 网络直接知道 WCT 在哪 |
| 探索 | 高斯(独立) | **OU(时序相关)** | 多步飞向 WCT 的概率大增 |
| Warmup | 2000 | **5000** | 更多充电经验种子 |
