# 审稿实验：环境配置与冻结策略评估

本次新增的是训练环境和评价基础设施。网络结构、奖励公式、能量安全层方法保持原实现；新增的 DARS batch-size 参数仅用于显式缩小试运行规模，正式默认值仍为 512。`train_unified.py` 默认采用多样化热点训练；直接创建 `UAVEnv()` 仍使用固定轮换参考模式。

## 热点划分（当前候选协议）

保留原来的三个热点组合：A={0,1}、B={1,2}、C={2,3}。每个组合仍有两个热簇，热/冷到达概率仍为 0.9/0.1，用户位置分布、任务大小与用户数量不变。

| 模式 | 每回合顺序 | 每段持续时隙 |
|---|---|---|
| `fixed` | A→B→C，按参考周期重复 | 默认 50 时隙参考周期内为 17、17、16 |
| `diverse`（训练及同分布验证） | 均匀选择 ABC、BCA、CAB 中一个，再循环 | 每段独立均匀取 12–20 |
| `unseen_order`（留出顺序） | 均匀选择 ACB、CBA、BAC 中一个，再循环 | 每段独立均匀取 12–20 |
| `unseen_timing`（留出持续时间） | 使用训练顺序集合 | 每段先等概率选 4–8 或 24–32，再在区间内均匀取整数 |

当前协议验证的是新顺序和新持续时间的适应性，不证明对所有可能热点过程、热点位置或任意规模的泛化。训练不读取留出模式的运行结果。训练入口拒绝 `unseen_*` 配置；验证只使用训练热点分布及独立种子。正式测试协议应在调参完成后固定；本次 smoke 使用的场景用于开发检查，不用于选取模型或正式结论。

环境分别使用初始化、用户位置、任务、热点四个随机数流，算法探索/PER 抽样不会推进环境随机数。每个时隙为所有用户抽取任务大小，即使该用户未激活，保证不同热点模式下任务随机数的消耗一致。显式 `reset(seed=...)` 可重放场景。

训练网络种子为 `seed`，第 `ep` 个回合环境种子为 `1000000 + seed*100000 + ep`，不同训练种子使用不相交的环境种子区间；验证从 100000 开始；测试默认从 200000 开始。算法间使用相同的训练/评估种子。评估入口检查测试种子与该模型训练、验证种子无交集。随机数实现变化意味着相同的旧整数种子不再复现旧版本轨迹。

## 时域、电量及 WCT

- `battery_capacity` 决定电量上限、状态归一化与原有低电量惩罚的比例分母。`initial_energy` 只决定重置电量。
- `horizon` 决定回合终止时刻，不改变热点切换速度。
- 时间特征定义为 `min(current_step / time_reference_slots, 1)`，默认参考值 50。延长时域时保持参考值不变，超过参考时刻后饱和为 1。它不再表示延长回合的剩余时间；正文需说明这一约定。时间维度未增加。
- `wct_indices` 从原有 WCT 位置中选择保留节点；状态仍为每架 UAV 到最近节点的距离和方向，维度不随节点数量变化。
- `wct_power` 是每个 WCT 的总输出上限；UAV 接收功率上限仍保持原 `P_TH`。不是把充电公式的所有参数同时缩放。
- `energy` / `all` 预设枚举所有 3、2、1 节点子集并分别报告，避免只挑选有利位置。联合压力场景目前只是一组候选设置。
- 零充电用原有 `--nowct` 或功率 0；配置不接受空 WCT 集合，以免最近节点观测无定义。

## 统计口径

逐回合训练数据在 `<algo>.train.jsonl`，训练配置和运行信息在 `<algo>.manifest.json`，同分布验证数据在 `<algo>.validation.json`。原有 `.npz` 字段保留。

冻结评估按场景保存 JSON，包含每回合数据及可选逐时隙轨迹；`summary.csv` 为紧凑表；`report.json` 包含完整协议、模型文件哈希、硬件/软件信息和跨训练种子汇总。

- 生存：全部 UAV 能完成指定时域，按实际执行时隙计数；被拒绝的尝试不计生存步数。安全搜索未找到候选不等于已经证明不存在任何可行动作。
- 最低电量：初始、每个已执行时隙飞行后和服务后的最小值，按 UAV 及系统分别记录。拒绝动作不计入未执行候选的电量。提前失败的回合仍纳入最低电量统计。
- 能耗：飞行、悬停、计算能耗及总和；同时保存累计值和每个已执行时隙的平均值。未执行任何时隙时平均值为 `null`，不伪造为零。
- 充电：`energy_in` 是收集量，`energy_charge_overflow` 是容量截断溢出，`energy_charge_accepted` 是扣除溢出后的接受量；后者不是最终电池净增量。沿用现有服务阶段能量记账假设。
- SLRR：`slrr_executed` 只平均已执行时隙；`slrr_fixed_horizon` 使用固定时域作分母，未执行时隙贡献为零。后者是评价口径，不是实际模拟了退出后的本地执行。未执行回合的前者为 `null`。
- 决策耗时：状态预处理、策略推理、动作映射、安全层、关联和资源分配；排除任务生成、移动场景模拟、延迟/奖励统计、日志和学习更新。固定设备/线程，先预热，GPU 同步计时。包含被拒绝的尝试，因为它们也实际占用决策时间。报告每回合平均及 P95，再跨回合汇总；“平均回合 P95”不能称为所有时隙合并后的总体 P95。训练阶段计时含探索，只把冻结评估计时用于在线开销表。
- 生存概率的 Wilson 95% 区间分别在每个训练模型内计算；跨训练种子给出均值和种子间样本标准差，不把同模型下的大量回合冒充独立训练重复。

修正了两个热点时序错误：先归零再生成首次任务；先推进时钟再生成下一状态的任务。此外，贪心及优先级贪心基线现在收到物理单位状态和实际 WCT 子集，避免电量被重复归一化或飞向已移除节点。

## 运行

工作目录为仓库根目录。已验证 Python 3.12、NumPy 2.3.5、PyTorch 2.15.0 CPU 环境；具体版本以保存的 manifest 为准。仅运行这些入口需 NumPy、PyTorch；测试使用标准库 unittest。

小规模流程检查（20 回合训练、128 步预热、batch=32、3 回合验证、8 类场景各 3 回合评估）：

```bash
python tools/run_review_smoke.py --tag my_smoke
```

正式训练示例（保持正式默认 batch=512、预热=8000；训练回合预算需依实际收敛检查确定）：

```bash
python train_unified.py --algo per_sac_cvx --episodes 5000 --seed 42 --tag formal_seed42 --env-config experiments/train_diverse.json --eval-episodes 50
```

其他算法/消融在相同配置下分别训练；通过不同 `--seed` 和 `--tag` 获得独立训练模型。不要把 smoke 的短预热、小 batch 默认带到正式实验。训练入口默认保存最终模型，不自动基于正式测试结果选最佳检查点。

固定模型进行压力和热点评价：

```bash
python evaluate_suite.py --manifests results/formal_seed42/per_sac_cvx.manifest.json --suite all --episodes 100 --seed 200000 --output results/formal_seed42/eval_all --threads 1
```

`--manifests` 可以传多个算法/训练种子的 manifest；每个 manifest 对应同目录下的模型文件。需要 `config.py` 与训练时的快照一致，避免悄悄改变物理模型。

自定义单因素测试，无需重训练：

```bash
python evaluate_suite.py --manifests results/formal_seed42/per_sac_cvx.manifest.json --suite custom --scenario-file experiments/custom_stress_example.json --episodes 100 --output results/formal_seed42/eval_custom
```

自定义入口只允许改变初始电量、时域、WCT 子集/功率和预先定义的热点模式，保留容量、时间编码及训练/测试规则划分。更改网络结构或训练超参数的敏感性实验仍需分别训练。旧 `run_sensitivity.py` 是改全局配置并重训的旧入口，与这里的冻结评估用途不同。

复核代码：

```bash
python -m unittest discover -s tests -v
```
